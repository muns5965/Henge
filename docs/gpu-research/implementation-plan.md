# 구현 순서와 완료 기준

각 단계의 완료는 소스 확인, 컴파일 성공, 자동 시험 통과, 실기기 실행을 구분해 판정합니다. CI 통과만으로 실기기 성공을 표시하지 않습니다.

## 단계 구분

- **문서·분석 단계** (S1–S3, 현재 진행 가능): 소스 확인과 시험 실행만 필요합니다.
- **선정 게이트 G0**: 외부 엔진과 셰이더 변환기 중 무엇을 채택할지 정합니다. 기능 비교 완료, Android 호환성 확인, 라이선스 검토 결과가 있어야 통과합니다.
- **Android 시험 단계** (S4–S6): NDK와 실기기가 필요합니다.
- **연결 단계** (S7–S10): 선정된 엔진 기준으로 진행합니다.

## 단계표

| 단계 | 내용 | 선행 조건 | 완료 기준 |
|---|---|---|---|
| S1 | llc 경로 해결 후 SKIP 2건 재시험 | 없음 | 두 시험 PASS 또는 원인 기록 |
| S2 | PVG 헤더 파서 확정 | 없음 | 파서 함수와 채택 구조체 기록 |
| S3 | 명령 네임스페이스 비교표 완성 | S2 | `(채널, 형식, opcode)` 기준 표 완성 |
| S3a | pvg-vulkan·libapplegfx 실행 시험 (ICD 환경) | 없음 (S3와 병렬) | 시험 실행 결과 기록. 실행 전에는 "미실행" 유지 |
| G0 | 선정 게이트 | S3, S3a, 라이선스 검토 | 채택 엔진과 셰이더 변환기 결정, 결정 기록 |
| S4 | NDK arm64-v8a 컴파일 (GitHub 러너) | NDK 확보 | 컴파일 성공, 스텁 미사용 확인 |
| S5 | Android에서 라이브러리 로딩과 Vulkan 초기화 | S4 | 실기기에서 Vulkan 장치 탐지 |
| S6 | 독립 Vulkan 렌더링 시험 (메모리 별칭 미사용) | S5, G0 | 실기기에서 렌더 결과 확인 |
| S7 | Henge PVG 프로토콜·메모리·스탬프 연결 계약 구현 | S3, G0 | 어댑터 단위 시험 통과 |
| S8 | 스탬프 재현 시험 후 단조 규칙 채택 여부 결정 | S7 | 역순 완료·순환·경쟁 시험 결과 기록 후 결정 |
| S9 | 실제 macOS 게스트 그래픽 명령 실행과 화면 검증 | S6, S7, S8 | 게스트 명령 결과가 화면에 표시됨 |
| S10 | 메모리 별칭 런타임 시험 (필요 시) | S5 | 데이터 일치, 실패 시 복구 확인 |

## 순서 조정 근거

- 기존 계획은 S6 메모리 별칭을 하드웨어 렌더링 시험의 선행 조건으로 두었습니다. 독립 Vulkan 렌더링 시험은 Henge의 게스트 메모리 별칭 없이 수행할 수 있으므로, 이 의존성을 제거했습니다 (S6, S10).
- S2–S3와 S3a는 병렬로 진행할 수 있습니다.
- G0 전에는 S7 이후 구현을 시작하지 않습니다. 엔진을 정하지 않은 채 어댑터를 구현하면 재작업이 생깁니다.
