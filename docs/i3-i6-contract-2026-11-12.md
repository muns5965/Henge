# I3~I6 공통 계약: 벤더링 쪽 수명 인터페이스 (2026-11-12)

I3·I4/I5·I6을 병렬로 구현하기 위해 **먼저 고정하는** 단일 인터페이스. 사용자 승인("검토 및 병렬구현", 2026-11-12 08:33)의 범위는 I3, I4·I5, I6이며 I10·`main`·FDR(B/C)·libusbmuxd(F)·G는 범위 밖이다.

## 1. 인터페이스
`third_party/libimobiledevice/src/hv_life.{h,c}` (빌드 스크립트가 `src/*.c`를 모으므로 자동 포함). 벤더링 쪽은 이 헬퍼만 호출하고, 호스트 레지스트리 형식을 직접 알지 않는다. **ops가 설치되지 않은 상태(NULL)에서는 모든 헬퍼가 "허용"을 돌려주고 아무것도 하지 않는다 = 기존 동작 불변(원칙 7).**

| 헬퍼 | 의미 |
|---|---|
| `hv_life_task_begin(kind,&gen)` | 0=등록됨(카운터++), -1=거부 → 스레드를 만들지 않는다. `gen`은 완료 때 쓴다 |
| `hv_life_task_end(gen,kind,failure)` | 작업의 **마지막 동작**(공유 객체 접근이 모두 끝난 뒤) |
| `hv_life_task_create_failed(gen,kind,failure)` | `thread_new` 실패 시 등록 해제(+실패 기록) |
| `hv_life_terminate_requested()` | 호스트가 취소·닫기를 요청했는가 (원자 읽기) |
| `hv_life_conn_add(fd,&gen)` | 0=등록됨(호스트가 다른 스레드에서 `shutdown` 가능), -1=거부 → 연결을 쓰지 않는다 |
| `hv_life_conn_remove(gen,fd)` | 0=모든 참조가 돌아옴, `close(fd)` 허용; **-1=`close(fd)` 금지(fd를 연 채 둔다)** |

종류: `HV_LIFE_K_ASYNC`(I3), `HV_LIFE_K_PROXY_CTRL`, `HV_LIFE_K_PROXY_CONN`(I6) = 레지스트리 `HvRegKind`와 같은 값.

## 2. 규칙 (세 작업 공통)
1. **연결 소유는 한 체계뿐**: `idevice` 연결(I5)과 프록시 소켓(I6)은 모두 `hv_life_conn_add/remove`를 쓴다. 별도 참조 카운트·이중 해제 금지. `close(fd)`는 `conn_remove == 0`일 때만.
2. 등록은 사용 **전**, 해제는 닫기 **전**. 이미 닫은 fd는 등록 목록에 남기지 않는다(fd 번호 재사용 경쟁).
3. 태스크: `begin` 성공 후에만 `thread_new`; 실패면 `create_failed`; 성공이면 스레드 마지막 동작이 `end`.
4. 호스트 취소(`hv_restore_session_cancel`)는 종료 플래그를 올린 뒤 등록된 모든 연결에 `shutdown(SHUT_RDWR)`을 호출한다(참조를 잡은 채, 락 밖). **`shutdown`이 닿지 않는 곳**: `connect()` 진행 중(미등록)·등록되지 않은 소켓 — 이 경우 취소는 해당 호출이 스스로 끝날 때까지 지연된다(I6에서 별도 수단).
5. 최소 diff, 후크 없을 때 반환값·동작 동일(NULL 후크 회귀 시험 필수).
6. 호스트: `hv_restore_session_begin()`이 ops를 설치하고 IDLE 복귀 지점(`end`/`abort_start`/`release_idle`)에서 제거한다(`host/restore_session.c`). 시험: `tools/session-reg-test.sh`의 `life`, `life_cancel`.

## 3. 완료 조건(검토 반영, 통합 전 필수 4개)
1. 길이 접두 부분 수신 결함 수정+회귀 (`property_list_service.c`, **I4와 함께 별도 커밋**)
2. join 실패 시 종료 확인 없는 자원 해제 방지 (F 경로: `libusbmuxd` 변경은 범위 밖이므로 **호스트 쪽에서 `client_free` 반환 불가 → 위험으로 기록, 변경은 별도 승인**)
3. 프록시 `connect`의 취소 가능한 연결 방식 (I6: 비차단 `connect`+기한부 `poll`+등록, 호출자 오류 코드 계약 호환 확인)
4. C14 참조 반환·fd 재사용 경쟁 시험 (I5)
