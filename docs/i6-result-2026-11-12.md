## 호환성
- `socket_connect()`는 변경하지 않았다. 프록시만 `rp_connect_cancelable`(등록 fd, 비차단 connect, 100 ms 슬라이스 poll, 5000 ms 한계, `limd_glue_connect_guard` 동일 호출, 실패는 -1+errno)을 쓴다. `socket_connect`의 다른 호출자: `idevicerestore/src/fdr.c:561`(구성에서 제외), 변경 없음. **정정**: 1단계 문서의 "`socket_connect`는 시간 제한이 없다"는 틀렸다 — glue에는 `CONNECT_TIMEOUT 5000`이 있다(1단계 s3lib의 '>3000 ms'는 이 5초 한계 안이었다). 정지가 아니라 **취소 불가**(fd 미공개)가 정확한 결함이다.
- `getaddrinfo`는 취소되지 않는다(호스트 이름 해석 중 취소는 해석이 끝날 때까지 지연).
- 정리 도중 `thread_join`이 실패하면 노드·클라이언트를 해제하지 않고 누수시킨다(살아 있을 수 있는 스레드 아래에서 해제하지 않기 위함). ctrl 완료 보고에 실패 값 1.
- 기존 이중 `close`(송신 실패 분기와 끝부분)를 단일 `rp_sock_close`로 정리했다.

## 남은 문제
- libusbmuxd `use_tag` 데이터 경쟁(T13, 범위 밖).
- 연결 스레드 목록은 제어 스레드 종료 때까지 늘어난다(원래도 그랬음, 상한 없음).
- 장치 쪽 연결(`reverse_proxy_client_new`→`idevice_connect`)의 취소는 I5(연결 등록) 병합 뒤에 효과가 있다.
- 호스트 `global_quit_flag` 쓰기(`install.c`, `restore_preflight.c:341`)는 일부 비원자(`ST` 매크로 사용 여부 확인 필요) — 이번 범위 밖.
