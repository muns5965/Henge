## Case 1: Godot #116990 and PR #119639  -- PARTLY (misstated on failure type)
READ: https://github.com/godotengine/godot/issues/116990 (created 2026-03-02, closed 2026-05-25), PR https://github.com/godotengine/godot/pull/119639 (by blueskythlikesclouds, created 2026-05-21, merged 2026-05-25).
- Device: Samsung Galaxy S20 5G, Android 12, Snapdragon 865 / Adreno 650. Godot 4.6/4.6.1 regress vs 4.5.1. Driver version not given in the issue.
- Failure: SIGSEGV (fault addr 0x18) in a worker thread at startup, memory corruption inside the Adreno 650 shader compiler (per the Godot rendering maintainer relaying Skyth). NOT a VK_ERROR_UNKNOWN return. Vulkan, ubershader (feature-everything pipeline variant) specifically; specialised shaders did not crash.
- What narrowed it: the 4.6.1 ubershader SPIR-V has 100 constants vs 88 in 4.5.1; a debanding PR bringing it to 96 fixed it for one reporter; 3,000 dummy constant operations in the specialised shader did not crash; literal-constant edits were inconclusive. PR text: compiler crashes when an ubershader uses too many constant literals (author's hypothesis; range of affected drivers unknown; author also reproduced on an Adreno 630 custom ROM).
- Merged workaround (READ from the .patch): 15 files. Reads the driver info string via VK_KHR_driver_properties in drivers/vulkan/rendering_device_driver_vulkan.cpp (new _get_device_properties and _check_driver_workarounds; hunks around -615 and -684), sets a new `disable_ubershaders` flag in a new DriverWorkarounds struct (servers/rendering/rendering_device_commons.h) when vendor is Qualcomm and the driver info contains the compiler prefix EV031.32.02. RenderForwardMobile (servers/rendering/renderer_rd/forward_mobile/render_forward_mobile.cpp) then drops the ubershader iteration count from 2 to 1, forces the ubershader flag on pipeline fetch, and skips ubershader precompile. Cost: pipeline-compile stutter.
- Correction to the claim: compiler string is "EV031.32.02.01"/"EV031.32.02.XX" prefix; it is matched on the driver-info string, not a literal "Compiler Version: ..." prefix (INFER: that wording is what the Adreno driver info string looks like; the PR text only says the version prefix). Adreno 650, not 8xx; crash, not -13.
- Shared trigger with our module (INFER): very large shader with many constants/literals; uber-style (all features in one module). Our module has float/half literal constants (not counted). Their compiler (E0xx.32) is older than ours (E031.50).
- Suggests rows: constants-count row (dedupe/merge constants, or replace literal constants with a UBO/spec-constant load; Godot maintainers listed "dummy UBO instead of literals"); "disable uber / specialise" row (strip unused branches via spec constants), which matches the Godot workaround.

## Case 2: Cemu #2029  -- PARTLY (core claim confirmed; "VS-only rasterizer-discard pipeline" NOT-FOUND)
READ: https://github.com/cemu-project/Cemu/issues/2029 (created 2026-08-15, open; 2 comments).
- Device: Windows 11 ARM64 (Cemu native ARM64 port), Adreno X1-85, Vulkan 1.3, driver build f22d572733 (2026-05-22), compiler E031.50.36.00, driver branch pp165.
- Failure: repeated "Failed to create graphics pipeline. Error -13" (VK_ERROR_UNKNOWN); invisible geometry in Breath of the Wild. 105 failing pipelines shared one trait: each VS/FS pair had exactly one fragment input (semantic 254 / passParameterSem254) with no matching vertex output.
- What narrowed it: editing 21 cached fragment SPIR-V shaders to replace that input with a constant removed the failures; other hypotheses (gl_FrontFacing, unordered-compare opcode, vertex input, depth/blend/raster/robustness state) made no difference. NVIDIA tolerates the mismatch.
- Fix (reporter's, not merged by maintainers; maintainer Exzap called it a known limitation and suggested a fork): keep SPI_PS_INPUT_CNTL DEFAULT_VAL and synthesise the missing VS output from it.
- No mention in issue or comments of rasterizer discard or a VS-only pipeline: that part of the claim is NOT-FOUND (MISSTATED).
- Independent confirmation: ZeldaWWHDRecomp PR #30 (https://github.com/ZeldaWWHDRecomp/ZeldaWWHDRecomp/pull/30, merged 2026-10-06; Adreno 830 and Adreno 750; driver/compiler not stated): two pixel shaders read passParameterSem254 that VS never writes -> vkCreateGraphicsPipelines VK_ERROR_UNKNOWN; workaround on failure: replace unmatched PS inputs with constant vec4(0) and recompile, else cache an empty pipeline and skip draws. (READ)
- Shared trigger with ours (INFER): our FS has 12 Location decorations vs a separate VS (translator reports "stage_link: 0 mismatch fixed, 0 missing zeroed"), so linking is already handled, but verify on the failing linked pair: any FS Input without a VS Output at the same location/component/type/interpolation (incl. flat vs smooth, half vs float width). Cheap, high-value row.
- Suggests rows: FS-input/VS-output exact-match audit; replace every FS input with a constant (one at a time, bisect); VS-only / minimal-FS rows as a control (the VS-only pipeline is a plain control, not a Cemu finding).

## Case 3: clpeak #219 / commit 70dce47, llama.cpp #28635 / #29952  -- PARTLY; several details MISSTATED
READ clpeak #219: https://github.com/krrishnarraj/clpeak/issues/219 (created 2026-10-04, closed 2026-10-21). Xiaomi 17 Pro, SM8850, Adreno 840, Android 17, Adreno Vulkan driver 0842.44.1, Shader Compiler E031.50.19.29, apiVersion 1.4.295. SIGSEGV null-deref in libllvm-qgl.so from vkCreateComputePipelines (COMPUTE, not graphics) for VK_KHR_cooperative_matrix fp16 A/B with fp16 accumulator at 64x64x16; crash only when the accumulator reaches the matrix multiply-add through an OpPhi (produced by spirv-opt SSA rewrite / glslc -O). Other combos (0 phis, mixed fp16/fp32) return VK_ERROR_UNKNOWN; fp32 accumulator and a QCOM-register 6-phi path build fine.
READ commit 70dce47805c1 (2026-10-04, 4 files +121/-8): withholds only the fp16xfp16+fp16 cooperative-matrix row when VkPhysicalDeviceDriverProperties driverID equals Qualcomm proprietary (so Turnip unaffected). Gate in src/vulkan/coopmat.cpp (runCoopMatrix ~L260-280, helper ~L115-145); driverID plumbed via src/vulkan/vulkan_device.cpp queryDriverInfo and include/vulkan/vk_peak.h; NOTES.md documents. No shader change.
READ llama.cpp #29952: https://github.com/ggml-org/llama.cpp/issues/29952 (2026-10-04, closed not_planned by stale bot). Same finding as clpeak; llama.cpp's shader generator already omits -O for coopmat shaders, which avoids the crash. Driver/compiler version not in body. No Turnip/lavapipe mention.
READ llama.cpp #28635: https://github.com/ggml-org/llama.cpp/issues/28635 (2026-09-09, open). Adreno 830 (RedMagic 10 Pro, Android 15, Vulkan 1.3.284; also HONOR AAK-AN00 driver 0.800.74): vkCreateComputePipelines returns VK_ERROR_UNKNOWN (-13) for mul_mat_vec_q4_k (q4_k family only; 38 subgroup variants tested). Original shaderc/NDK theory was RETRACTED by the reporter (bad extraction). Pipeline succeeds without VkSpecializationInfo, fails with the module's own default spec constants, and fails when BLOCK_SIZE >= 32. Comment 3 (ArborPopuli): Mesa/Turnip and lavapipe both succeed on the same GPU. Comment 4 (flyingdoog): Adreno 830 (compiler E031.47.18.51) fails; Adreno 840 (driver 0.842.46, compiler E031.50.19.31, Vulkan 1.4.295) passes the same SPIR-V; fp16 enabled. Maintainer 0cc4m: Qualcomm shader compiler has "a number of bugs". No workaround merged for it.
Classification of the claim: "-13/SIGSEGV with FP16 + OpPhi" is true only for clpeak/#29952 (compute, cooperative-matrix, SIGSEGV; -13 only for other variants). "Turnip and lavapipe built the same SPIR-V" is true only for #28635 comment 3 (not #29952). "Adreno 830/840 compile failures" true but all COMPUTE. Compiler versions .29 (clpeak) and .31 (#28635 c4, a passing device) are correct. None involve graphics/fragment shaders.
- Shared trigger with ours (INFER): our module has 0 OpPhi (confirmed), so the OpPhi mechanism is NOT applicable unless spirv-opt/driver-side transforms add phis; FP16 is present in ours (Float16, v4half function signatures, StorageBuffer16BitAccess). Spec-constant presence/values and workgroup size are not relevant to fragment. Same compiler family E031.50.19.x as ours (.27), so a shared compiler bug class is plausible but unproven.
- Suggests rows: FP16->FP32 (all half to float; caveat Float16 caps and 16-bit storage); a row that explicitly adds/removes OpPhi via spirv-opt --ssa-rewrite / reduce-load-size to see if phis change behaviour; "no -O" (already no phis here, but check the linked module).

## Case 4: Vita3K #4141, O3DE #625, AMD-Gfx-Drivers #34
- Vita3K PR #4141 -- PARTLY. READ: https://github.com/Vita3K/Vita3K/pull/4141 (created 2026-09-19, CLOSED NOT MERGED, by amurgshere). Adreno 650 (Retroid Pocket 5), SIGSEGV inside vkCreateGraphicsPipelines (VERTEX shader). Compiler crashes when a vertex shader writes only some components of a constant-indexed element of a Private vec4 array with >=19 elements (writes including .w fine; <=18 elements safe). Vita3K declared the output register bank as 20 vec4s. Workaround proposed: declare 16 vec4s, setting auto/on/off, cache-key bit, Android-only crash-guard logging shader hashes. Not merged. Shared trigger (INFER): partial-component writes / insert-dynamic on large Private arrays; ours has 373 OpVectorInsertDynamic and 405 64-bit-indexed dynamic ops, so test dynamic indexing converted to constant/OpSwitch or to array-of-scalars.
- O3DE #625 -- MISSTATED (wrong repo). o3de/o3de#625 is an unrelated PR ("Better AP error message when missing image present"). The real report is o3de/o3de-extras#625 (https://github.com/o3de/o3de-extras/issues/625, created 2023-11-30, open): Quest Pro (Adreno 650), vkCreateGraphicsPipelines returns VK_ERROR_UNKNOWN for a PBR forward-pass shader (graphics, multiview). SPIR-V from DXC 1.7.2308 fails, from DXC 1.6.2112 works. Qualcomm offline compiler (AOC 3.0, compiler version E031.42.19.00) fails on both, asserting in RegIndex/SHARED_CONST_BEGIN metadata generation (1.6.2112) and "Unsupported Instruction in Fast Isel" (1.7.2308). Workaround: use older DXC. Closest pure graphics -13 + E031.x report; shows same SPIR-V semantics emitted differently by the front-end changes the outcome. Suggests rows: re-emit the module through a different producer (spirv-opt --legalize / -O0 vs -Os, glslang/DXC round trip), and run Qualcomm's offline compiler on the module (if obtainable) to get the assert text.
- GPUOpen AMD-Gfx-Drivers #34 -- MISSTATED/irrelevant. READ: https://github.com/GPUOpen-Drivers/AMD-Gfx-Drivers/issues/34 (2024-11-24, closed 2025-08-12). AMD Radeon RX 6700 XT, driver 24.10.1, vkCreateGraphicsPipelines -13 for glslc -O output (works without -O) after a vertex shader switched to GL_EXT_buffer_reference. AMD said a fix was ready internally; no version given. Not Adreno, no size link. Only generic lesson: spirv-opt -O output can break a driver that accepts unoptimised SPIR-V; the reverse row (do NOT optimise) is cheap.

## Case 5: further public reports found (WebSearch + GitHub search)
- d7vk #274 (https://github.com/WinterSnowfall/d7vk/issues/274, 2026-11-04, open): Galaxy Z Fold8, Adreno 840, proprietary Vulkan 0.842.19 (1.4.295; Turnip could not create an instance). DXVK graphics pipeline for a fixed-function FS with colour-key (discard on colour compare) via spec constant fails with -13; same shaders without colour key compile. Graphics-pipeline-libraries unsupported. Compiler version not stated. Closest same-GPU graphics -13 report. Suggests: OpKill/OpDemoteToHelperInvocation and discard paths. Our module: OpKill count 0, so discard is probably already absent; row = confirm and also try with a discard added/removed.
- alondero/aerogauge-recomp PR #61 (merged 2026-09-20): Adreno 750 v0762.41, compute pipeline -13 for a 16-bit byte swap expressed with bitwise OR; fixed by writing XOR. Shows the compiler can reject on a specific opcode pattern. Suggests: audit bit ops (OpBitwiseOr/OpBitFieldInsert/OpShift with 8/16-bit types), our module uses Int8/Int16 capabilities. Related open: alondero/automobililamborghini-recomp#367 (Adreno 750 0x802FA029, 5 compute pipelines -13, cause unknown).
- vello #1957 (2026-09-28, open): Adreno 7xx (Nothing Phone 2), 8 compute pipelines -13; trigger: one struct type used as a Workgroup array element and also stored whole into a storage-buffer array; fix: store member by member. Suggests: whole-struct stores / OpCopyObject / OpLoad-OpStore of struct to StorageBuffer in our module (we have StorageBuffer struct pointers; Private/Function aggregate copies).
- wgpu #10621 (Adreno X1-85, struct passed by value reads wrong field), not -13; mentioned as another by-value-struct/function-call hazard (not opened in depth: title only, INFER relevance: noinline helper functions with aggregate params/returns).
- NOT-FOUND: any public report of -13 from vkCreateGraphicsPipelines on Adreno 8xx with input attachments / framebuffer fetch / VK_EXT_rasterization_order_attachment_access / dynamic_rendering_local_read (GitHub searches for rasterization_order_attachment_access + Adreno returned 0 hits; local_read only returned unrelated waterui design notes). NOT-FOUND: reports about 761-style huge counts of 64-bit dynamic vector indices; NOT-FOUND: SPIR-V 1.4-specific Adreno bug. NOT-FOUND: Mesa freedreno/turnip issues for A8xx big fragment shaders and any Qualcomm release-note statement of this bug (searches only returned generic Mesa release notes and Qualcomm forum/docs pages; I did not open them).
