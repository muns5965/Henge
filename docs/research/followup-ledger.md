## Evidence notes 2026-11-27 (dump analysis, no device; spec minima below are from memory, NOT checked against the Vulkan spec)
- L1: sample count is decoded only for texture descriptors (arm64_resources.c:621-684; >1 refused as TEXWHY_C_MSAA). The PSO decoder has no sample-count field; no PSO field was proven to be one (123 unique PSO blobs; attachment tokens carry only index/pixfmt/blend/writeMask). INFER: rasterSampleCount is omitted as a default. All 191 mapped texture descriptors in all dumps have samples=1. Decoding a PSO sample count needs a dump from a guest that requests rasterSampleCount>1. DeviceInfo MSAASamples=4 untouched.
- L2: no COLOR_ATTACHMENT check at render_target.c:147-152, iosurface.c:89-95, pipeline.c:532/559; COLOR_ATTACHMENT_BLEND is never queried (pipeline_build.c:405 enables blend from the PSO; composite.c:118 / pipeline.c:1119 hard-code blendEnable). Already checked: create_image (arm64_resources.c:367-385) incl. depth/stencil and D24S8->D32S8 fallback. Real dumps use only vkfmt 44 (mtl 80, B8G8R8A8_UNORM, x935) and 97 (mtl 115, R16G16B16A16_SFLOAT, x348) as colour attachments; all 1107 cap_pass have depth=0, stencil=0. Both formats are expected to be mandatory colour-attachment+blend formats in the spec (unchecked), so a missing feature there would be a driver bug; a real gap is plausible only for non-mandatory formats, none seen in dumps. => L2 is low priority until a non-mandatory format shows up.
